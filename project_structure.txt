[!] CRITICAL MANDATORY DIRECTIVE FOR ALL AI AGENTS AND AUTOMATIONS [!]
--------------------------------------------------------------------------------
1. CHANGE STAGING IS STRICTLY REQUIRED:
   Every code change, architectural modification, bug fix, or feature MUST be
   immediately staged in `docs/CHANGELOG.md` (and mirrored in `docs/change.md`) under the `## [Unreleased]` section.
   Entries MUST record both:
   a) Detailed Technical Changes: Exact classes, methods, signatures, and low-level mechanics for engineers.
   b) Plain-English End-User Impact: Clear, non-technical explanation of what changed and why it matters to the user without developer jargon.
   When a release is created (via `Build.cmd`), this section is published as
   the public human-readable changelog / "What's New". DO NOT commit or deliver
   work without updating `docs/CHANGELOG.md`.

2. DOCUMENTATION SYNCHRONIZATION:
   AI agents must NEVER modify source code without updating the corresponding
   module documentation in `docs/`. Keep minimaps and descriptions 100% accurate.

3. COM & STANDALONE THREADING CONSTRAINTS:
   - DeskGuard packages as a standalone self-contained single-file application
     with built-in COM interop enabled for WebView2 and Outlook MAPI.
   - All WebView2 initialization and UI interaction must occur on the STA thread
     with active Windows message pumping.
   - All Outlook COM/MAPI calls MUST run exclusively on the dedicated STA thread
     coordinated by `OutlookStaCoordinator`. Never invoke COM from thread pool workers.
